# Changelog

## 0.6.0 (2026-10-19)

Labels where they are required, or where nobody can tell; nothing where they are only voluntary. An agent had stamped a voluntary EU "AI" icon on a pixel-art image for a social post, and the owner removed it: a label is a compliance tool, not decoration. Required labels look and behave exactly as in 0.5.0, and `stamp`, `render`, `place` and the human-made labels and pack do not change.

- **Voluntary labels are off by default.** When the verdict is "not required" and every deciding fact is known, `label` (MCP `label_image`, library `labelImage`) stamps nothing and writes no file, not even to `--out`. The result has `stamped: false`, `output`, `label` and `disclosure` null, `alt` with the description alone (no label sentence), and a `note` on how to opt in. Over MCP no image content comes back. `decide` (MCP `decide_label`) returns `next: null` and an `optIn` line for a voluntary AI label; the CLI prints "No label needed" instead of a next command and skips the placement advice (`--explain` keeps it). A human-made verdict keeps its `next`, because that label is the user's own claim.
- **`unsure`.** `--realistic unsure` (also `--realistic=unsure`), MCP `realistic: "unsure"`, library `realistic: 'unsure'`; the same for `--public-interest` and `--editorial-review`. Booleans keep working. The verdict starts with `UNSURE, LABEL AS A PRECAUTION`, `required` is `"unsure"`, `precaution` is `true` and `unsure` lists the arguments answered that way. `label` stamps the label, and its `note` says it was added because the answer was unsure.
- **Precautionary labels use the required form.** That is the EU icon alone by default, not the word: a precautionary label stands in for one that may be a duty, and the icon is what Measure 1.1(a) of the Code asks for; `--short` adds the word as for any label.
- **Asking first.** A missing fact still gets one question and exit code 2. The question now says what to do when nobody can answer, and `decide`'s `next` for `required: "unknown"` is the same `decide_label` call with that fact `"unsure"` (CLI line included), so an agent that cannot ask has a defined path. The MCP error for a `label_image` call without `realistic` says the same.
- **`voluntary`.** One opt-in with the same name everywhere: `--voluntary` on `label` and `decide`, MCP `voluntary: true` on `label_image` and `decide_label`, library `voluntary: true`. It restores voluntary labels in the smallest form, the EU icon alone, as in 0.5.0. `ai-labels init --voluntary` writes an `AGENTS.md` block whose command carries `--voluntary`, for projects that label every AI image. There is no other project config.
- **`only_if_required` is deprecated.** It describes what is now the default, so `--only-if-required` and `only_if_required` are still accepted and have no effect; a result where it was passed says so in its `note`. Together with `voluntary` it is refused as a contradiction.
- **What agents read.** The MCP server instructions, the `label_image` and `decide_label` descriptions, SKILL.md, the `init` block and the README now say: call `label_image` after generating an image; it labels only when required or unsure and does nothing for voluntary cases unless opted in. The old line that a voluntary label is stamped because labelling AI images is good practice is gone.
- **Schemas.** `label_image` output: `required` is a boolean or a string, `precaution` is new, and `output`, `alt` and `disclosure` describe the unlabelled case. `decide_label` output: `next` can be null; `optIn`, `precaution` and `unsure` are new. The `realistic`, `public_interest` and `editorial_review` inputs take a boolean or `"unsure"` (`anyOf`).

Migration: callers that want the 0.5 behaviour, a label on every AI image, pass `--voluntary` (MCP `voluntary: true`). Callers that passed `--only-if-required` get the same results as before and can drop the option. Code that read `decide().next` for a voluntary verdict now gets `null` unless it passes `voluntary: true`.

## 0.5.0 (2026-10-18)

The smallest label that does the job: the EU "AI" icon alone, 18 px as shown on a phone. Also placement for HTML pipelines, shaped regions, boxes to keep clear, platform safe zones and brand colours, from the feedback of a production ad pipeline. Stamped labels change size and pixels for every default stamp (see behaviour changes below); `render` output is unchanged for every call 0.4.0 accepted.

- **The icon form.** `--form icon` (or `--icon`; MCP `form: "icon"` or `icon: true` on every label tool): the official EU disc alone, black or white, whichever stands out more from the spot, with a thin ring in the letters' colour (a sixteenth of the disc, so a 16 px disc is an 18 px badge). No text, no content-type icons, no pill; the disc keeps its exact proportions. In `render` (SVG, PNG, and HTML as inline SVG with the label sentence for screen readers), `stamp`, `label` and `place`. It takes no colour, and a human-made label or part keeps its words. Results report `label.disc` (black or white).
- **Forms by name.** `--form icon|minimal|short|full` (MCP `form`) next to the flags `--icon`, `--minimal`, `--short`, `--full`, which stay as aliases; two different forms are refused as before.
- **Legible down to 18 px.** The smallest legible label, as shown, is 18 px for the icon and for a label with a word (was 24), and still 20 px for the minimal pill. The floor comes from legibility, because the Code of Practice and the icon page set no size: a letter must be 5.65 CSS px tall to be read with the EU minimum eyesight for driving (visual acuity 0.5) on a phone at 32 cm, so the EU disc is 16 px and a word is set at 10.5 px; `rules.md` and the README give the sources. A 1080 px wide image gets a 50 px label (was 67), 56 px minimal.
- **Laid out at the size seen.** `stamp` and `place` lay the label out at its height as shown and scale it to the file, so the word is 10.5 px or more on the phone (0.4 drew a 67 px stamp at file size, which showed the word at about 9.7 px). Under 24 px a label with words gets a thinner inset (1 px at 18, 3 px at 24) instead of smaller type; at 24 px and up the geometry is that of 0.4. `renderLabel` takes `designHeight` for this; without it `render` draws exactly as before.
- **`--height` with `--display-width`.** `stamp` now takes both: that size, laid out for that display width. With the image's own width it reproduces the 0.1 to 0.4 stamps pixel for pixel (see the README).
- **Place without stamping.** `ai-labels place <image>` (MCP `place_label`, read-only; library `placeLabel(input, opts)`) runs the same planning as `stamp` (form, size, shrink to fit, spot, colour, warnings) and writes nothing. It returns `box` in px, `boxPercent` in % of the image (two decimals, for CSS: `left`, `top`, `width`, `height`, `right`, `bottom`, and `anchor` with the sides to pin the label by) and `renderArgs`, the `render` options that draw the same label with the form always explicit, next to the `label` fields `stamp` reports, the alt text and the label sentence. Over MCP `renderArgs` are snake_case, so they go straight into `render_label`. The CLI prints the box in px and % and a ready `render` line, with values such as `'#1f7a52'` quoted for the shell.
- **Shaped regions.** `--region-path "<SVG path>"` (MCP `region_path`) in image px, or `--region-mask <png>` (MCP `region_mask`): inside where the mask's alpha is 50% or more, or its brightness when it has no transparency (also when its alpha is opaque everywhere); the mask is resized to the image. The region is the shape's bounding box. Each spot starts at its corner of that box and moves inward in small steps (bottom spots up, top spots down, side corners towards the middle) until the label and its margin lie inside the shape; a spot that does not fit before the middle is rejected, and the label shrinks when no spot fits. `--region`, `--region-mask` and `--region-path` are mutually exclusive. Path data is checked to contain only path commands and numbers. With file paths off (HTTP mode) `region_mask` is refused; `region_path` works.
- **Avoid boxes.** `--avoid x,y,w,h` (repeatable, px or %; MCP `avoid`, an array; a `;` inside one value separates boxes too): a spot where the label and its margin overlap a box is rejected. A given `--position` that overlaps one, or does not fit inside the shape, is refused. There is no face or person detector: SKILL.md tells agents to look at the image and pass boxes for faces, people, the product and text, because the busy score sees only texture.
- **Why each spot lost.** Results have `label.why`: for every spot not taken, `busy (score 9.1, free is 6 or less)`, `overlaps avoid box 1`, `does not fit inside the shape` (`within the safe zone` when the safe zone is what leaves no room), or `free, but bottom-right comes first`. `label.spots` keeps its 0.4 shape (scores only, for the spots the label could take). `reason` names the rejection of the bottom-right corner. When every spot is rejected, a usage error lists the reasons and suggests a smaller form, smaller avoid boxes or `--position`. The CLI adds a `skipped:` line for spots lost to an avoid box or the shape.
- **Safe zones.** `--safe-zone <preset>|top,right,bottom,left` (MCP `safe_zone`), insets in px or % of the image, trims the area the label may use (together with the region). One preset: `meta-reels` (14% top, 35% bottom, 6% sides), from the Meta Ads Guide for Instagram Reels, checked 2026-10-18; the table in `place.mjs` keeps the source and date of each preset. Other platforms take their numbers from their own templates as custom insets. Results report `label.safeZone` (name, or null, and the insets in px).
- **Brand colours.** `--palette #hex,#hex` (MCP `palette`): the colour that stands out most from the spot, used exactly as given with white or dark text for 4.5:1, or the neutral pill with a `colorNote` when none reaches 1.5:1. Not with `--color` or `--theme`.
- **HTML label at a given height.** `render --format html --height N` (MCP `render_label` with `height`) makes the pill exactly N CSS px tall, laid out like the SVG label at that height: the mark is the SVG's disc (N minus an inset of 0.125N, or for words under 24 px 1 px at 18 growing to 3 px at 24), the padding is the inset less the 1px border, and `min-height` is lifted, so the mark, the content-type icons and the words grow with N. The words get the size the SVG label uses at that height. Same minimums as SVG (18 px, 20 minimal). Checked in a Chromium-based browser from 18 to 48 px, within 1/64 px. Without `--height` the HTML is unchanged and keeps its 12 px floor.
- **`label.cssHeight`** in `stamp`, `label` and `place` results: `displayHeight` rounded up to whole CSS px, the `--height` for an HTML label over the shown image. `renderArgs.height` is the whole px at or under it, the height `stamp` lays the label out at, so an SVG drawn with `renderArgs` and scaled to the box is the stamped label.
- **`decide`** no longer adds `minimal: true` to the next step: `next.arguments` carry no form, and its note says the EU icon alone meets Measure 1.1(a), the word is encouraged (1.1(b)) and comes with `--short`, and the label sentence goes in the alt text and, for a deep fake, in a visible caption.
- **Version in every result.** Every JSON result of the CLI, the results of `stamp`, `label`, `place`, `render`, `decide` in the library, and every MCP structured result carry `version`; the MCP output schemas list it.
- **Docs.** README: an "Upgrading" section: `--short` for the 0.4 look at the new size, `--short --height <n>` with the 0.4 size rule, and `--full --position top-left --height <n> --display-width <image width>` with the 0.3 size rule for the 0.1 to 0.3 stamp, checked pixel for pixel against 0.1, 0.3 and 0.4; the minimal SVG from `render` is the same from 0.1.0 to 0.5.0. README "Size, place and colour" explains the 18 px floor with its sources, and `rules.md` has a "How small a label can be" section and mapping rows for Measure 1.1(a), (b) and (c). "Which label" in README and SKILL.md has a rule for ads and feeds: put the word on the image (`--short`) unless the label sentence is in the first visible line of the caption (Code of Practice Sub-measure 1.2.1). SKILL.md has a section for HTML pages, ad templates and UI (`place`, then `render` with `renderArgs` at `boxPercent`), and rules for `--avoid`, shapes, safe zones and `--palette`; it says what `--color auto` reads. `decide`'s placement advice, `rules.md`, the `ai-labels init` block (the icon by default, and one line on `--avoid`), the MCP tool descriptions and server instructions and the CLI help follow.

Behaviour changes:

- **Default form.** `stamp`, `label` and `place` give every AI label (generated, modified, basic), required or voluntary, the icon form. 0.4 gave a required label the short form and a voluntary one the minimal form. `--short` gives the word back. Human-made labels, labels with a human-made part, and labels in a colour (`--color`, `--palette`) keep the short form. `render` keeps the short form as its default.
- **Smaller labels, new pixels.** The minimum is 18 px as shown (was 24 for labels with words), and labels with words are laid out at the size they are seen. Every default stamp changes size and pixels; a 1080 px wide image gets a 50 px label instead of 67 px.
- **Refusals.** `render` and `stamp` accept labels with words from 18 px (was 24); the hints that pointed to `--minimal` for smaller spots now point to the icon form, since the minimal pill (20 px) is no longer the smallest.
- **`--color auto` with a region** (box, mask or path) reads the accent from the part of the image outside the region when that part is at least 20% of the image, so incidental colours in the AI photo (a red cable, the sky) do not set the label colour. With `--region` and `--color auto` together, the label colour, and so the pixels, can differ from 0.4.0. `label.color.source` stays `auto`; the new `label.color.sampled` says `outside the region` or `whole image`.
- `render --format html` used to ignore `--height`; it now sets the pill height.

## 0.4.0 (2026-10-18)

The smallest legible label, in the least invasive spot, optionally in the colours of the image. These change the defaults: labels made with 0.3 look different when made again.

- **Form.** The default wording is now the short one, the EU "AI" disc and one word ("Generated", "Modified", "Human-made"), as on the EU icons. `--full` (MCP `full`) gives the full wording; `--short=false` does the same. `decide` adds `minimal: true` (and `--minimal` in its CLI line) to the next step of a voluntary AI label, so `label` and `label_image` stamp voluntary labels in the minimal form; a form the caller passes wins. Every result reports `label.form`.
- **Size.** The automatic stamp size is the smallest legible one where the image is shown: 24 px tall with text and 20 px minimal at the display width, a phone (390 CSS px) unless `--display-width` says otherwise, never below that in the file and never above 512 px. A 1080 px wide image gets 67 px, or 56 px minimal (0.3: 65 px, about 6% of the shorter side). `--display-width` now sets the width the label is sized for, so a larger width gives a smaller label, down to the minimum. `autoHeight(width, { minimal, displayWidth })` replaces the 0.3 rule; the old call shape still works. Results always report `displayWidth` and `displayHeight`, and a `warning` when the label had to shrink below that size to fit.
- **Place.** `--position` defaults to `auto`: the bottom-right corner when it is free, else the freer of bottom centre and bottom left, else the top edge. A spot counts as free when the mean brightness gradient under and around the label is 6 or less (on a copy at most 320 px on the long side). Results report `placement`, `reason` and the score of every spot (`spots`). New fixed positions: `bottom-center` and `top-center` (0.3 default: top-left).
- **Region.** `--region x,y,width,height` (MCP `region`), in px or % of the image, for a graphic where only one part is AI: the label is sized to fit that part and placed in its least invasive spot.
- **Colour.** `--color <hex>` (also in `render` and `--format html`) draws an opaque pill in that colour, with white or dark text, whichever keeps 4.5:1; the EU disc stays the official black or white. `stamp` and `label` also take `--color auto`: the accent colour of the image (the hue with the most colour among clearly coloured pixels, weighted towards stronger colours), darkened or lightened in OKLCH until the text reaches 4.6:1, then the dark or light tone that stands out more from the spot. An image without a clear accent, or a spot where the tone would blend in (under 1.5:1), keeps the neutral pill and says so (`colorNote`). `--theme` and `--color` together are refused, and so are `--short` and `--minimal`.
- Fixed: `--theme auto` (MCP `theme: "auto"`), the documented stamp default, was refused when passed explicitly.
- SKILL.md has a new rule for agents: the smallest legible label in the least invasive spot unless the user asks otherwise, with when to use `--region` and `--color auto`. `ai-labels init` writes the same in one line. README, `decide` placement advice, `rules.md` and the CLI help follow.
- The "Made by a human" pack and the documentation images are unchanged; their generators now ask for the full wording explicitly.

## 0.2.0 (2026-10-17)

Works with any agent, and in one call for agents that generate images.

- `label <image> --realistic|--no-realistic`: decides the label for an AI image (generated, or modified with `--modified`) and stamps it in one step. Without the realism answer it asks the same question as `decide` and exits with code 2. It stamps voluntary labels too; `--only-if-required` skips them. Also takes `--creative`, `--lang`, `--text`, `--description`, `--position`, `--display-width`, `--out`, `--force` and `--no-metadata`. `<image>` can be an http(s) URL with `--out`.
- MCP tool `label_image`, the same step for agents: `realistic` is required, the image comes as `input` (file path or http(s) URL) or `input_base64` (with optional `mime`), and `return_image` adds the labelled image as image content. Base64 or URL input without `out` writes nothing and returns the image.
- `stamp_image` also takes an http(s) URL or `input_base64`, and `return_image`. Downloads: http and https (https only in HTTP mode), up to 5 redirects, 50 MB, 30 s for the whole download, never through a proxy from the environment. Stamping refuses SVG input and images over 50 megapixels before decoding them.
- Every MCP tool has a `title`, an `outputSchema` and returns `structuredContent` next to the same JSON as text.
- MCP protocol 2026-07-28 next to the earlier ones: `server/discover`, per-request `_meta` with the protocol version, `resultType` and `serverInfo` in results, and `UnsupportedProtocolVersion` (-32022) errors listing the supported versions. Clients that start with `initialize` work as before; `initialize` now also accepts 2025-11-25.
- HTTP mode: `ai-content-labels-mcp --http [--port 8787] [--host 127.0.0.1] [--token <secret>] [--allow-files] [--allow-origin <origin>]`. Streamable HTTP on `POST /mcp` with JSON responses, 202 for notifications, 405 for GET and DELETE, header checks for 2026-07-28 requests (-32020 on a mismatch). Bound to 127.0.0.1 by default; any other address needs a bearer token (`--token` or `AI_CONTENT_LABELS_TOKEN`). Requests with an Origin header that is not allowed get 403, and on localhost the Host header must be local. File paths are off unless `--allow-files`, and plain http URLs and URLs that point at loopback or private addresses are refused. At most 3 tool calls run at once (503 with `Retry-After` beyond that), and a malformed request gets an error response instead of stopping the server. Over MCP, error messages name the argument (`text`) with the CLI option in brackets.
- `init [--write] [--file AGENTS.md]`: a short block for AGENTS.md, GEMINI.md or Copilot instructions that tells agents to label the images they make. `--write` adds it between marker comments and updates it in place on the next run.
- Node library: `import { labelImage, stampBuffer, decide, renderLabel, renderHtml, stampImage, officialIcon } from 'ai-content-labels'`. `stampBuffer` labels an image held in memory and returns a Buffer.
- The skill follows the Agent Skills format (`name`, `description`, `license`, `metadata`) and runs from its own folder or through `npx`, so Codex, Gemini CLI, Copilot and Cursor can use it as well as Claude Code. It puts `label` first for images the agent made itself.
- README: setup for each agent and recipes for what to do after an agent generates an image.

## 0.1.0 (unreleased)

First public version: images and labels for web pages.

- `decide`: the Article 50(4) checklist (deep fakes, public-interest text, editorial review, creative works, audio) with the EU icon to use, placement, accessibility notes and the label sentence. Based on the AI Act, the Commission's Article 50 Guidelines (20 July 2026) and the Code of Practice on Transparency of AI-Generated Content. When the deciding fact is missing (`--realistic` for image, video and audio; `--public-interest`, then `--editorial-review` for public-interest text) it returns `UNKNOWN` with one question, names the argument in `missing` and exits with code 2 instead of guessing.
- `decide` prints a short answer by default: a one-line verdict (also the `verdict` field), the next command to run, the label, where to put it and what screen readers need. `--explain` adds the basis, notes and sources; `--json` is always complete. The label sentence is the `disclosure` field. After a verdict, the `next` field (JSON and MCP) holds the next call: `tool`, `arguments` to pass unchanged, `fill` (what is still to supply) and the `cli` line. Its alt-text advice shows a placeholder (`<what the image shows>`), not a ready description.
- `decide` wording checked against the sources: territorial scope and what counts as professional use (Guidelines paras 13 and 19-20), video labels shown at the start, repeated at regular intervals where possible and at least after breaks, as the Code asks (Sub-measure 1.2.2(b); Guidelines para 143), with the whole video as this project's recommendation, repeated spoken disclaimers in long audio (Sub-measure 1.2.3) with the example in the label language, spoken and transcript routes for blind viewers (WCAG 1.2.5, 1.2.1), no animation (WCAG 2.2.2), an explanation of the human-made mark, which the Code encourages for own labels (Measure 2.1, internal compliance process) and the Unfair Commercial Practices Directive for false human-made claims.
- `render`: labels with the official basic EU icon, text in English or Polish, content-type icons and an optional "Made by a human" part; SVG (with `lang`), PNG or WebP; 4.5:1 text contrast on any backdrop. `--format html` writes the label as real text with a stylesheet (`--css`) that follows the page's colour scheme (`light-dark()`, with a fallback for older browsers) and forced colours, wraps whole words in narrow columns and keeps type at 12 px or more. The SVG scales down in a narrow container. Spaced capitals are never set below 10 px.
- `stamp`: burns a label into one JPG, PNG, WebP, AVIF or TIFF file, sized for the image (about 6% of the shorter side, at least 2.5% of the longer side, 28 to 512 px) and in the theme that stands out more from the image. `--kind` is required, so no file gets an AI claim by default. `--display-width` sizes the label for the width the image is shown at (390 for a phone: at least 28 px tall there), and every stamp reports `minDisplayWidth`, the narrowest display width at which the label stays 24 px tall. Keeps the EXIF, colour profile and XMP of the original and adds an IPTC DigitalSourceType to the XMP. Refuses to overwrite an output or to stamp a labelled file again unless you pass `--force`; every stamp writes the project's XMP marker (also for human-made labels and with `--no-metadata`), so a renamed labelled file is refused too. Writes through a temporary file and refuses a second parallel write to the same output. Folders, animated images and GIF output are refused with what to do instead. The summary names the pill colour and warns when `--allow-low-contrast` drops below 4.5:1 (`wcag: false` in the result).
- Alt text: `--description` puts what the image shows before the label sentence; results carry both `alt` and `disclosure` (the sentence alone). Without a description `alt` is null and, for labels with an image or video in them, `altMissing` says what to pass; `render` adds `labelAlt` and prints a ready `<img>` line for a label image.
- Languages: all 24 EU language codes. English and Polish have built-in wording; the others take `--text` (and `--human-text`) and tag the SVG and HTML with that language.
- Input checks: stray words (an unquoted `--text`) and fractional heights are refused.
- `--minimal`: no text, only the author mark (EU "AI" disc, or a hand in the same disc) and the content-type icons, down to 20 px. Labels with text are at least 24 px tall.
- The hand in the human-made mark is a filled raised hand with five fingers (Heroicons "hand-raised", MIT), 0.62 of its disc tall at every size, in SVG, PNG and HTML alike, so it matches the weight of the bold "AI" letters.
- `eu`: the official EU icons, unchanged. `icons`: the content-type icons.
- MCP server (`decide_label`, `render_label`, `stamp_image`, `eu_icon`) with strict arguments and tool annotations, Claude Code plugin and skill.
- The CLI installs as `ai-labels`, the name the help and `decide` print, and as `ai-content-labels` for `npx`.
- The skill folder carries its own third-party notices (`NOTICE.md`, the Lucide ISC, Feather MIT and Heroicons MIT texts in `assets/icons/LICENSE.txt`), so a plain copy of it keeps them.
